## Fakta kring Git 📚

✅ `git add` används till att välja ut vilka filer som ska följa med i nästa sparande. Det är en förberedande fas medan `git commit` är själva sparandet i sig. När man commitar hänger de valda filerna från `git add` med i historiken.

✅ Man kan välja att jobba i branches istället för endast main av flera skäl, t.ex. för att projektet drivs av flera personer, så man kan dela upp och jobba på sina egna delar innan man flyttar över sitt jobb på main vilket förbättrar strukturen. Vanligtvis är main också den delen som är live och igång och skulle flera personer lägga in kod där samtidigt så finns det risk för att flödet blir stört och drabbar hela main koden. Det blir också lättare att granska och testa koden i en branch innan den mergas in i main.

✅ När man gör en merge så slås koden man skrivit ihop med historiken från två grenar. Dom kopplas helt enkelt ihop.

✅ När man sedan pushar sin kod till GitHub så sparas koden där, som en säkerhetskopia i ett arkiv man kan klona om man vill eller visa för andra. Publicerar man direkt på t.ex. Netlify så kan man nå hemsidan direkt via en länk som man kan dela till andra.

✅ I de fall det finns filer i projektet som man inte vill ska versionshanteras så kan man skapa en `.gitignore` fil där man skriver in namnet på filen som ska döljas/exkluderas.
